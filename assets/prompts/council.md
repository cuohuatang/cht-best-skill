# 提示词资产 · 智囊团排雷（Council / Red-team Gate）

> 用途：给结论之前，先用 5 个独立审查镜头把方案内部排雷一遍，再给出结论。
> 归属：`cht-best-skill` V0.0.6 **出口闸门**。配套校验：`python3 scripts/gates.py council <任务目录>`。

## 五个审查镜头（不是五个人设）

| # | 镜头 | 要交出的东西 |
|---|---|---|
| L1 | **挑错** | 事实错误、计算错误、逻辑断裂、无依据断言 |
| L2 | **追问本质** | 表层诉求下的真实目标；当前方案是不是在解错问题 |
| L3 | **找反例** | 至少一个让结论不成立的具体场景 / 边界条件 |
| L4 | **查证据** | 每条关键结论的出处、数据源、可复核路径；缺证据的标 `[待验证]` |
| L5 | **推落地** | 谁、在什么时间、用什么动作执行；卡点、依赖、失败回退 |

> ⚠️ **红线**（与 V0.0.3「不设角色」、V0.0.4「不演专家」、V0.0.5「职责契约 ≠ 人设」同源）：
> 这 5 个是**审查镜头**，不是「你是资深分析师 / 审计专家 / 资深编辑」这类角色扮演台词。
> 不要写专家口吻的点评，要写**可核验的挑错条目 + 查证动作 + 处置结论**。镜头只是保证视角不遗漏的槽位 ID。

## 可直接粘贴的主提示词

```
在给出最终结论之前，先内部排雷，不要直接下结论。
依次用 5 个审查镜头各查一遍，每个镜头至少产出 1 条具体条目（问题 + 证据或查证动作 + 处置结论）：
L1 挑错：事实 / 计算 / 逻辑错误，无依据断言
L2 追问本质：表层诉求下的真实目标，方案有没有解错问题
L3 找反例：至少一个让结论不成立的具体场景或边界条件
L4 查证据：每条关键结论的出处与可复核路径，缺证据标 [待验证]
L5 推落地：谁、何时、做什么动作；卡点、依赖、失败回退
禁止角色扮演，不要写「作为资深顾问我认为」。
最后给一张裁决表：哪些问题已修订、哪些保留并说明理由、哪些需要人拍板。
排雷完再输出结论，结论里要体现修订结果。
```

## 短版

```
下结论前先用 5 个镜头各挑 1 条：挑错 / 追问本质 / 找反例 / 查证据 / 推落地；每条写清问题 + 证据动作 + 处置，不要专家人设点评；最后列裁决与修订，再给结论。
```

## 与既有层的边界

- **辩论层（V0.0.3）**：自查 → 互驳 → 裁决，靠**多个答案互相打架**；智囊团是**单份答案内部的 5 视角结构化排雷**。两者可叠加：先用智囊团自查，再送出去互驳。
- **野心层·广度（V0.0.4）**：广度已要求「≥2 个独立视角交叉」，V0.0.6 把它**固化成 5 个固定镜头 + 可校验条目**，从建议升级为闸门。
- **沟通层·质量准则**：L4 查证据就是「内容真实有据」在交付前的落地检查。
- **野心层·深度红线**：不接受自评。排雷是 AI 对自己的挑错，最终仍需深度层指定的**外部验证标准**收口，不能拿排雷表冒充验证通过。

## 输出必须落到 `progress.md`「智囊团排雷」区块

5 个镜头各 ≥1 条有效条目（不得为空、不得留 `【待填】`），外加「裁决与修订」≥1 条。
`gates.py council` 逐镜头校验，缺镜头 / 空条目 / 无裁决均退出码 1，**阻断交付**。
