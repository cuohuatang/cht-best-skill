# 提示词资产 · 反向提问（Ask-first / Clarify Gate）

> 用途：开工前让 AI 主动把信息模糊、缺失的点一次问清，避免自行脑补跑偏。
> 归属：`cht-best-skill` V0.0.6 **入口闸门**。配套校验：`python3 scripts/gates.py clarify <任务目录>`。

## 可直接粘贴的主提示词

```
在动手之前，先别执行，先反向提问：
1. 通读我给的全部材料，先自查——凡是能从材料、文件、命令、公开资料里查到或合理推出的，自己解决并列出清单，不要拿来问我。
2. 然后只挑出「不确认就一定会跑偏」的高杠杆模糊点：目标边界、验收口径、数据源、受众、约束、时间线、既有假设。
3. 把这些问题合并成一批，一次性发给我；每个问题写清「如果不确认，你会默认什么、结果会怎么跑偏」。
4. 我答复后，一口气把活干完，不要边做边追问、不要每步都问「这样可以吗」。
5. 若某个问题我没答，明确写出你采用的默认假设并标注 [假设]，不要悄悄脑补。
```

## 短版（贴进任意提示词末尾）

```
动手前先自查：能查到的自己查；只对不问就会跑偏的点批量问一次，别逐条打断我；问完一次性做完；未答项标 [假设]，别脑补。
```

## 使用边界

- ✅ 适合：多步骤、跨会话、要落盘产物的任务（完整档 / 组织档）。
- ❌ 不适合：单轮问答、纯闲聊、琐碎确认（消除档）——见 M1 启用闸门。
- **与心法 06 的调和**：06 说「只在真阻塞时问、别拿琐碎确认打断人」。本提示词不是推翻它，而是把「真阻塞」**提前识别出来并合并成一次提问**：先自查过滤掉大部分能自己解决的问题，剩下的高杠杆点一次性问完，问完就放手干。反对的是「边做边问」和「一上来甩 20 个问题」。
- **与心法 03 的咬合**：AI 看不到的东西它就会编。反向提问是 03 的前置动作——把「缺上下文」从「事后编造」变成「事前问清」。
- **与沟通层（格赖斯）的咬合**：提问本身受数量准则约束——信息不多不少，只问高杠杆项；受质量准则约束——未答项必须标 `[假设]`，不许假装是事实。

## 输出必须落到 `task_plan.md`「0.1 反向提问」区块

四段缺一不可：

| 段 | 内容 | 校验要求 |
|---|---|---|
| A 自查已解决 | 自己查到/推出的项，不用问人 | ≥1 条有效内容 |
| B 高杠杆模糊点 | 每条写「模糊点 ｜若不确认会：…」 | ≥1 条，且两侧都填实 |
| C 一次性提问批次 | 合并后的 Q1…Qn | ≥1 条，编号连续 |
| D 处置状态 | 每条 Q 的答复，或明确默认假设（标 `[假设]`） | **C 里每个编号都必须闭环** |

`gates.py clarify` 逐段校验，任一未闭环退出码 1，**阻断开工**。
