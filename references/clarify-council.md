# 反向提问 & 智囊团排雷（V0.0.6 详解）

> 两条高阶提示词分别卡在任务的**入口**与**出口**：
> **反向提问**＝动工前把模糊点一次问清，不让 AI 脑补；
> **智囊团排雷**＝下结论前用 5 个镜头把方案内部挑一遍，不让带病结论出门。
>
> 和 V0.0.4 / V0.0.5 一样，**这一层不是文档，是闸门**：模板必生成 → `gates.py` 逐项校验 → 未闭环退出码 1。

---

## 1. 为什么单独立一层

前六层各自管一段，但有两个缺口一直靠"自觉"补：

| 缺口 | 以前靠什么 | 问题 |
|---|---|---|
| **入口**：材料不全时 AI 会自己编 | 心法 03「缺上下文先去要」、沟通层「标待确认」 | 是建议，没有"问过没有"的落盘证据；长任务里必然滑回脑补 |
| **出口**：给结论前的内部排雷 | 辩论层「自查→互驳→裁决」、野心层广度「≥2 视角交叉」 | 依赖多个 AI 会话互驳；单 Agent 单次交付时经常被跳过，且没有固定视角清单 |

V0.0.6 把这两处做成**单 Agent 也能每次执行**的结构化区块 + 机器可校验闸门。不新增第四个记忆文件——入口区块嵌进 `task_plan.md`，出口区块嵌进 `progress.md`，三文件结构不变。

---

## 2. 两处必须调和的冲突

### 2.1 反向提问 vs 心法 06「别盯着屏幕等它，只在真阻塞时问」

这是本轮最容易被做错的地方。若按字面「先问清**所有**模糊、缺失的点」，Agent 会退化成每步都问「这样可以吗」的确认机器，正好违反 06，也违反沟通层的数量准则。

**调和后的执行定义**：

```
先自查 → 过滤 → 只对高杠杆点批量问一次 → 问完一口气干完 → 未答项标 [假设]
```

| 步骤 | 判定 | 落到模板哪一段 |
|---|---|---|
| 自查 | 能从材料 / 文件 / 命令 / 公开资料查到或合理推出的，**自己解决，不问人** | A 自查已解决 |
| 过滤 | 只保留「不确认就一定会跑偏」的点：目标边界、验收口径、数据源、受众、约束、时间线、既有假设 | B 高杠杆模糊点（含「若不确认会」） |
| 批量问 | 合并成**一条消息**发出，不逐条打断 | C 一次性提问批次 Q1…Qn |
| 闭环 | 每条 Q 要么有答复，要么写明默认假设并标 `[假设]`；**不许悄悄脑补** | D 处置状态 |

> 一句话：**不是"多问"，是"把该问的一次问对"**。06 禁的是琐碎确认和边做边问，不是禁开工前的一次澄清。

### 2.2 智囊团「5 位顾问」 vs 不设角色 / 不演专家

V0.0.3 黄仁勋法明令「从不给 AI 设角色」，V0.0.4 野心层红线是「不演专家」，V0.0.5 又立了「职责契约 ≠ 角色人设」。这次却要"模拟 5 位不同视角的顾问"，表面第三次打架。

**调和**：沿用同一条逻辑——**招的是岗位/槽位，不是演员**。

| 写法 | 判定 |
|---|---|
| `L1 挑错：第 3 段"转化率提升 12%"无数据源，需回查 CRM 原始表 → 已补来源` | ✅ 审查镜头 + 可核验条目 |
| `作为资深数据分析师，我认为这个结论略显乐观……` | ❌ 人设台词，直接违反红线 |

「5 位顾问」= **5 个固定审查镜头**（挑错 / 追问本质 / 找反例 / 查证据 / 推落地），是防视角遗漏的槽位 ID；校验器只查**有没有 5 段、每段有没有实质条目、有没有裁决**，从不查"像不像顾问"。这和 `pstack.py` 里校验职责契约字段、不查"像不像张良"完全同构。

## 3. 字段规范

### 3.1 `task_plan.md`「0.1 反向提问」（入口）

```
<!-- CLARIFY_BLOCK_START -->
### A. 自查已解决（不用问人）
- 已从材料/文件/命令中查到并确认：…

### B. 高杠杆模糊点（不问就会跑偏）
- 模糊点 1：… ｜若不确认会： …

### C. 一次性提问批次（合并成一条消息发出）
- Q1：…

### D. 处置状态（每条必须闭环）
- Q1 → 答复 / 默认假设（标 [假设]）：…
<!-- CLARIFY_BLOCK_END -->
```

闸门规则（`gates.py clarify`）：

1. 两个区块标记齐全，A/B/C/D 四节齐全；
2. A ≥1 条有效内容；
3. B ≥1 条，每行必须含 `｜若不确认会：` 且**分隔符两侧**都填实；
4. C ≥1 条 `Q<数字>：`，且内容填实；
5. D 中**C 的每个 Q 编号都必须出现**且处置内容填实（答复或含 `[假设]` 的默认）；
6. 任何位置残留 `【待填】`、空值、少于 2 字符 → 判未填。

> D 的编号闭环是最硬的一条：它保证"问了的问题真的有了着落"，而不是列完问题就开工。

### 3.2 `progress.md`「智囊团排雷」（出口）

```
<!-- COUNCIL_BLOCK_START -->
### L1｜挑错
- 问题：… ｜查证动作/证据：… ｜处置：…

### L2｜追问本质
- …

### L3｜找反例
- …

### L4｜查证据
- …

### L5｜推落地
- …

### 裁决与修订
- 已修订：…
<!-- COUNCIL_BLOCK_END -->
```

闸门规则（`gates.py council`）：

1. 两个区块标记齐全，L1–L5 与「裁决与修订」六节齐全；
2. 每个镜头 ≥1 条有效条目，且建议含「问题 / 查证动作 / 处置」三段；
3. 裁决与修订 ≥1 条；
4. 残留 `【待填】`、空值、少于 2 字符 → 判未填。

## 4. 与七层的咬合

| 层 | 咬合点 |
|---|---|
| 心法 03 / 05 | 反向提问是 03 的前置（事前问清而非事后编造）；排雷条目是 05 要的证据的一种 |
| 心法 06 | 反向提问的边界条件：**一次批量、问完放手**，不退化成逐条确认 |
| 三文件 | 入口区块落 `task_plan.md`（计划期），出口区块落 `progress.md`（执行/交付期）；不新增文件 |
| 沟通层 | 数量准则约束提问量；质量准则要求未答项标 `[假设]`、缺证据标 `[待验证]` |
| 辩论层 (V0.0.3) | 智囊团是**内部 5 视角自查**，辩论层是**多答案互驳**；可叠加：`council` → 互驳 → 人裁决 |
| 野心层 (V0.0.4) | 广度「≥2 视角」升级为固定 5 镜头；深度的外部验证标准仍是最终收口，排雷表不能冒充验证通过 |
| 帝王团队层 (V0.0.5) | 组织档下，反向提问由张良在拆任务前统一做（避免 3-5 个 AI 各问各的）；智囊团由萧何编排，`handoff` 把挑错条目送回韩信修订 |
| M2 执行循环 | 两个闸门都是**第 0 段前置 / 第 5 步交付检查**，不计入 ≤5 基元 |

## 5. Agent 可执行协议

```bash
P=~/.codebuddy/skills/cht-best-skill/scripts

# 0. 野心升级（V0.0.4，仍最先）
python3 $P/verify_ambition.py ./agent-tasks/<任务目录> || exit 1

# 0.2 入口：按 assets/prompts/reverse-questions.md 提问并填 task_plan.md「0.1」
#    自查 → 高杠杆点 → 一次性批次 → 逐条闭环
python3 $P/gates.py clarify ./agent-tasks/<任务目录> || exit 1   # 未闭环阻断开工

# 1–4. 干活，边做边写 findings / progress

# 5. 出口：按 assets/prompts/council.md 排雷并填 progress.md「智囊团排雷」
python3 $P/gates.py council ./agent-tasks/<任务目录> || exit 1   # 缺镜头/无裁决阻断交付
python3 $P/gates.py verify  ./agent-tasks/<任务目录> || exit 1   # 一次查两道 + 交付总检
python3 $P/verify_ambition.py ./agent-tasks/<任务目录> || exit 1
# 组织档再跑：python3 $P/verify_team.py ./agent-team || exit 1
```

`gates.py seed <目录>` 可给 V0.0.5 及更早的任务目录**补齐两个区块**（不覆盖已有内容），便于老任务平滑升级。

## 6. 反模式

- 一上来甩 20 个问题、每步都问「这样可以吗」——把反向提问做成确认机器（违反 06 与数量准则）
- 自查段留空，把能查到的东西也拿去问人（没做过滤）
- 只列问题不做 D 段闭环，或者悄悄按自己猜的默认开干（脑补，违反 03）
- 材料缺失就先编一个占位数字顶上（老问题，入口闸门专门堵这个）
- 让 AI 写「作为资深顾问我认为……」的点评交差（角色扮演红线）
- 5 个镜头只写 2 个、或每镜头一句「无明显问题」敷衍（形式主义排雷）
- 挑出一堆毛病却没有任何裁决与修订记录，结论原样发出（排雷没进产物）
- 拿智囊团排雷表冒充野心层要求的**外部验证**（自评≠外部验证）
- 三个 AI 各问各的、把同一批问题重复抛给人（组织档应由张良统一收口）
- 琐碎单轮问答也强行走两道闸门（违反 M1 消除档，流程比活还重）

## 7. 自检三问

1. **入口**：能自己查的，我查了吗？问出去的每一条，是不是「不问就一定跑偏」？是不是**一次性**问完的？
2. **闭环**：C 段每个 Q，在 D 段都有答复或明写的 `[假设]` 吗？
3. **出口**：5 个镜头都交出了可核验条目吗？裁决与修订真的改到结论里了吗？

> 和 V0.0.4 那句实话一样：闸门保证的是**每次都做了、且留下了可查的闭环记录**；它保证不了问得够不够准、挑得够不够狠——那仍是人的判断（对应心法 10 与辩论层的裁决权）。
