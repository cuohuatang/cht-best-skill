# 三文件协议

## 为什么必须落到磁盘

上下文窗口会被压缩，`/clear` 会清空会话，跨天任务会换窗口。模型不记得昨天的事——**但磁盘记得**。

三文件不是文档，是**运行状态**。判断标准：如果现在断电，下一个人（或下一个会话）只靠这三个文件能不能接着干？能，就合格。

## 目录布局

```
agent-tasks/
└── 20261103-1140-重构定价页/
    ├── task_plan.md     地图：要去哪、分几段、现在在哪
    ├── findings.md      事实库：已经确认了什么，来源在哪
    └── progress.md      行车记录仪：做过什么、为什么这么选
```

一个任务一套，不复用、不混装。任务结束就冻结，不再改动——它是这个项目的历史档案。

## task_plan.md

**何时写**：开工时；每次切换阶段前。

**必须有**：

- 目标一句话（读一遍就知道要交付什么）
- 验收标准：可勾选、可核验，不写"质量好"这种没法判定的
- 阶段表：3–6 个阶段为宜，多了说明没想清楚
- 边界：明确不做什么，防止范围膨胀
- 当前阶段：永远只有一个

**不要**：写成完整方案书。计划要能被 30 秒读完，超了就是没提炼。

## findings.md

**何时写**：每拿到一条事实，立刻写——不要攒到最后，中途被打断就没了。

**字段规范**：

| 字段 | 要求 |
|---|---|
| 事实 | 一句话陈述，可独立理解 |
| 来源 | 文件路径 / URL / 谁说的 / 哪天测的，必须能追回去 |
| 置信度 | 高＝一手来源亲自核实；中＝可信二手；低＝推断 |
| 时间 | 记录时间，用来判断是否过期 |

**推测必须标 `[假设]`**。假设不是错，假装是事实才是错。

**"已排除"这一节最有价值**：写清试过什么、为什么不成立，避免下一个会话重复踩坑。

## progress.md

**两个区，节奏不同**：

- **状态快照**：每次更新**覆盖**，只保留最新。三行说清：当前阶段 / 已完成 / 阻塞。
- **日志**：只**追加**，不删不改。每条 = 时间 + 动作 + 结果 + 证据路径。

**决策记录**：记"为什么这么选"和"否掉了什么"。三天后你不会记得当时否掉的那个方案长什么样，但你会需要它。

**证据**：路径、命令输出、截图位置。没有证据的进度等于没做。

## 更新节奏

| 时机 | 动作 |
|---|---|
| 完成一步 | 追加 progress 日志 |
| 拿到事实 | 写 findings |
| 切换阶段 | 先改 plan 的"当前阶段"，再更新 progress 快照 |
| 交付前 | 三文件自检：plan 的目标是否达成、findings 是否有未验证项、progress 是否写完下一步 |

## 中断后恢复（4 步）

1. 读 `progress.md` 状态快照 + 最后一条日志 → 停在哪
2. 读 `task_plan.md` 当前阶段 → 该做什么
3. 读 `findings.md` → 已有什么事实，别重复调研
4. 只补缺口，继续推进

**恢复时不要做**：不要重读全部聊天记录（贵且乱）、不要重做已完成阶段、不要推翻已有结论除非找到反证。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 只写 plan 不写 progress | 中断即失忆 | 每步追加日志 |
| 事实不带来源 | 无法复核，等于编 | 每条写来源与置信度 |
| 把待办写进 findings | 事实与计划混淆 | 待办只进 plan/progress |
| 快照越写越长 | 失去"一眼看清"的作用 | 快照覆盖，历史留给日志 |
| 一个目录塞多个任务 | 上下文互相污染 | 一任务一目录 |
| 任务结束后继续改 | 历史档案失真 | 冻结，新任务新目录 |

## 最小可用版

嫌三文件重，可以只保留 `progress.md`（状态快照 + 日志）。这已经能救回 80% 的失忆事故。

但 `task_plan.md` 防跑偏、`findings.md` 防重复调研——这两个才是让长任务不烂尾的关键。
