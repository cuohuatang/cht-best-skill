# 帝王团队：组织层（让 AI 自己造班子、派活、干活）

> 原型：Lauren Tan（SpaceX / Grok Bot 工程负责人）"不把 AI 当工具，而是组建智能体团队，人管目标、AI 落地执行"的七条方法 + 三层架构 + 开源编排工具 pstack。
> 用户重构：**刘邦式治理**——刘邦（人）什么都不会，只定方向搭班子；张良（天才）用脑、韩信（地才）打仗、萧何（人才）管后方，三才各自再招人，层层分工。
> 体系定位：前面各层都在管**单个 Agent 怎么想/说/记/验/要**；这一层管**一队 AI 怎么组织起来真干活**。用户原话："让它真正能落实干活的能力而不是一个壳"。

---

## 一、为什么必须是"引擎"，不是又一篇心法

如果只把七条写成建议，结果一定是**壳**：读完很爽，干活时还是一个人对着一个 AI 手动搬信息。所以本层落到 `scripts/pstack.py`——一个纯标准库、真能跑的落盘状态机：

| 产物 | 作用 |
|---|---|
| `manifest.json` | 机器可读唯一事实源：花名册 / 任务台账 / 技能库 / 流转记录 / 查岗记录 |
| `ROSTER.md` + `agents/<id>/PROFILE.md` | 人读花名册与职责卡（输入/输出/验收/定时/汇报对象） |
| `agents/<id>/{outbox,inbox}/` | **独立输出区**——输出与人分开，出问题好排查 |
| `handoff` | **真的把上游产物复制进下游 inbox**，杜绝人工传话 |
| `skills/<name>.md` | 干成的方法固化，以后"用这个技能干 XX" |
| `reviews/<date>.md` | 定期查岗考核、升级调整 |
| `verify_team.py` | 硬闸门，未通过退出码 1，阻断派工与交付 |

一句话：**状态在磁盘、流转靠命令、边界靠闸门**，不靠 Agent 自觉。

## 二、三层架构与三才（帝王映射）

| 帝王位 | 三才 | 层级 | 职责 | 可自行招募 |
|---|---|---|---|---|
| **刘邦**（人）| — | 调度者 | 只定方向、搭班子、审最终结果；**不亲自干活、不做传话筒、不做思考型军师** | — |
| **张良** | 天才 | 决策层 | 理解任务、拆分成可派发子任务、定验收标准、跟进进度；**不写执行产物** | 专项参谋 |
| **韩信** | 地才 | 执行层 | 按分派清单真干活、产出可点开的证据 | 专项工程师（10-20 个临时实例） |
| **萧何** | 人才 | 编排层 | 维护三文件记忆、技能库、验证护栏、后勤；调用预设技能做标准化重复工作 | 账房 / 校验员 |

**递归分工**（用户核心）：萧何找人管后方、韩信找会打仗的人、张良只管用脑——`PROFILE.md` 里每个角色都有 `可自行招募` 字段，`hire` 支持继续捏人。

**3-5 上限 vs 数十个执行实例**：原文说单人可调度数十个 AI，用户却强调"3-5 个调教透的顶一整支杂牌军"。二者不矛盾，本层这样落地：

- **常设岗 3-5 个**（`MIN_AGENTS=3 / MAX_AGENTS=5`，`hire` 超编直接拒绝）——这是要"调教透"的三才班子
- **专项执行实例按需临时招募、不入常设花名册**——对应韩信手下 10-20 个专项 AI

判据：**常设=要长期调教与查岗的岗位；临时=干完即走的执行实例。** 别把十个半吊子塞进花名册。

## 三、七条实操 → 可执行动作（逐条落地）

| # | 原方法 | 本层落地 | 硬约束 |
|---|---|---|---|
| 1 | 先造「AI 人事 / AI 设计师」：按场景问清需求，生成职责清晰的角色，定期考核调整 | `init` 组团 + `hire` 捏人 + `onboard` 五问 + `review` 查岗 | `hire` 必填职责契约五字段，缺一拒绝；`review` 生成考核表 |
| 2 | AI 重质不重量，3-5 个调教透的顶一支杂牌军 | 常设岗 **3-5 硬上限** | 第 6 个 `hire` 被拒；`verify` 检查超编/缺编 |
| 3 | 别上来甩指令：先自报家门（我是谁/干啥/最烦啥），再问"咱俩怎么搭手" | `ONBOARDING.md` 三段契约（A 自报 / B 反问 / C 复述） | **未清空【待填】，`dispatch` 与 `verify` 均拦截** |
| 4 | 每次干成事儿立刻"把方法存成技能"，以后"用这个技能干 XX" | `capture` 固化 + `reuse` 复用（带 `reuse_count`） | 技能文件落盘，可同步备份 GitHub 攒公司资产 |
| 5 | 给 AI 专属邮箱/独立账号，输出跟你分开，好排查 | 每个角色独立 `outbox/`、`inbox/` + `PROFILE.md` 身份卡 | `verify` 检查每个岗位都有独立 outbox |
| 6 | **别当传话筒**：凡要手动把信息从 A 挪到 B，立刻停，反问 AI 怎么自动化 | `handoff --from A --to B` 真的复制产物到下游 inbox | 流转记录入 manifest；手写中转视为反模式 |
| 7 | 交代任务别打字：语音倒背景，最后"用你话复述一遍" | `ONBOARDING.md` C 段 + 派工单「AI 复述确认」字段 | 复述未确认不得开工（第 3 条同一闸门） |
| 配套 | 验证护栏、AI 自主核验、标准化重复工作全交 AI、人只审目标与结果 | `verify_team.py` + 职责卡 `acceptance` 外部验证标准 | 标记 done 却无 `evidence_path` 直接拦截 |

**核心逻辑**：刘邦只定方向搭班子，干杂活全丢给 AI；人保留**提问权、决断权、最终结果审核权**（与辩论层、野心层一致）。

## 四、关键调和：职责契约 ≠ 角色人设

这是本层最容易和前面几层"打架"的地方，必须说清：

- V0.0.3 黄仁勋法：**从不给 AI 设角色**，"你是某某领域专家"会拉高讨好属性，答案变成迎合而非真实。
- V0.0.4 广度层：多视角 = 交叉核验，**不是角色扮演台词**。
- 本层却要"捏职责清晰的 AI 员工""张良韩信萧何"。

**不矛盾，因为二者根本不是一回事：**

| | 人设（禁止）| 职责契约（本层）|
|---|---|---|
| 写法 | "你是资深战略专家，请用专业口吻…" | "张良：输入=目标+约束；输出=分派清单+验收标准；禁止=写执行产物；定时=on-demand" |
| 作用 | 给 AI 贴形容词，诱导它演 | 定义**接口**：输入/输出/验收/汇报/定时/上下游 |
| 风险 | 讨好、套话、顺着错误逻辑走 | 无——它是可校验的字段，不是台词 |
| 名字 | "专家"是身份暗示 | "张良"只是**槽位 ID**，用于索引与流转 |

所以 `PROFILE.md` 顶部写明"职责用动词描述，禁止人设形容词"，`manifest.json` 里每个角色都是结构化字段，校验器只查字段完整性，从不查"像不像张良"。**招的是岗位，不是演员。**

## 五、与既有各层的咬合

| 已有层 | 咬合点 |
|---|---|
| 心法 02 说要什么 | 刘邦的"定方向"就是 02；张良拆分不得臆造需求 |
| 心法 03/05 真上下文、要证据 | 派工单必填 `evidence_path`；handoff 传的是**原始材料**而非转述，避免信息失真 |
| 心法 08 一对话一任务 | 一任务一套 `ledger/Txxx` 派工单，天然隔离 |
| 心法 09 记录即记忆 | 萧何职责 = 维护 `findings/progress`，团队状态写进 `manifest.json` |
| 沟通层·方式准则 | 职责卡用短句/列表，不写散文式岗位描述 |
| 辩论层·互驳 | 多角色交叉校验走互驳流程；外部验证标准禁止自评 |
| 野心层·高度/深度/广度 | 张良拆分前先过 `verify_ambition.py`；广度"多视角"在此升级为**多岗位** |
| M2 IPO 基元链 ≤5 | 派工链同样 ≤5 个常设岗；组织层是前置，不占任务基元数 |
| M1 启用闸门 | 消除档（琐碎任务）**不组团**；只有完整档才 `pstack init` |
| 双闸门层（V0.0.6 入口/出口） | 反向提问由张良在拆任务前**统一批量问一次**（避免 3-5 个 AI 各问各的、重复打扰人）；5 镜头排雷由萧何编排，`handoff` 把挑错条目送回韩信修订，裁决记录入 `progress.md` |

## 六、每次怎么跑（Agent 可执行协议）

```bash
P=~/.codebuddy/skills/cht-best-skill/scripts

# 0. 只有完整档任务才组团（琐碎任务走 M1 消除档，别小题大做）
python3 $P/pstack.py init

# 1. 先自报家门 + 反问怎么搭手 + 让 AI 复述（填 ONBOARDING.md）
python3 $P/pstack.py onboard

# 2. 硬闸门：未通过不得派工
python3 $P/verify_team.py ./agent-team || exit 1

# 3. 张良拆分 → 派工（可按需 hire 第 4/5 个常设岗，超 5 拒绝）
python3 $P/pstack.py dispatch --to hanxin --task "..." --acceptance "..."

# 4. 韩信把产物落到 agents/hanxin/outbox/，然后自动流转给萧何，别手动搬
python3 $P/pstack.py handoff --from hanxin --to xiaohe

# 5. 干成事儿立刻沉淀技能
python3 $P/pstack.py capture --name "XX流程" --from-task T001 --method "1... 2..."
python3 $P/pstack.py reuse --name "XX流程" --task "下次的活"

# 6. 定期查岗迭代 + 交付前再过闸门
python3 $P/pstack.py review
python3 $P/verify_team.py ./agent-team
```

## 七、反模式

- 花名册塞十几个半吊子（违反 2，闸门拒绝）
- 一上来就 `dispatch`，没填 `ONBOARDING.md`（违反 3/7，派工被拒）
- 自己复制粘贴把 A 的产物发给 B（违反 6，应该用 `handoff`）
- 干完不 `capture`，下次从头教（违反 4，白折腾）
- 所有 AI 共用一个输出目录（违反 5，出问题查不出是谁干的）
- 给 AI 写"你是天才战略家"这种人设形容词（违反第四节调和，退回角色扮演）
- 让张良写代码、让韩信定验收（职责错位，查岗时升级调整）
- 琐碎任务也组团（违反 M1 启用闸门，流程比活还重）

## 八、一句话总结

> **刘邦只定方向搭班子，三才各管一摊并自行招人，杂活全丢给 AI；状态落盘、流转靠命令、边界靠闸门——把 AI 当员工养，而不是当工具使，更不是当演员演。**
