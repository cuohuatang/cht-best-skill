# Step −1 · 输入分流与提示词优化（V0.0.8 详解）

> 定位：**入口的入口**。用户「不会写提示词」时，先把一句糙话变成能干活的提示词，再进野心升级。
> **不新增第八层、不做第六道「每次必过」的闸门**——是条件触发的分流器：SKIP 时原样透传、零改动、零文件。

---

## 一、为什么放在「第一步」而不是再加一层

用户原话：**「首先第一步就要优化用户提示词」「一定要区分不是所有提示词都优化」**。

现有执行循环是 `0 野心升级 → 0.2 反向提问 → 0.3 决策关 → 0.5 组团 → 1..5`。野心升级负责「把保守目标改成结果导向」，但它**默认输入已经是一句合格的指令**；不会写提示词的人给的是「帮我搞个东西」——这时候连野心升级都无从下手。所以优化发生在所有步骤之前，编号 **Step −1**。

同时它**必须条件触发**：如果做成每次必过，用户每说一句「谢谢」都要被生成两版提示词，直接违反 M1 消除档、心法 06 和格赖斯「数量适量」。这与 V0.0.7 决策关「默认关闭、宁可少用」是同一条纪律。

```
用户输入
   │
   ├─ classify → SKIP ─────────────→ 原样执行（一个字不改、不落文件、不生成版本）
   │
   └─ classify → OPTIMIZE
          ├─ 落盘：init_task.py → prompt_opt.py init --input "<原文>"
          ├─ 填 S/A/B/C/D/V1/V2/E/F → verify
          └─ 拿高阶顶配版去跑 0 野心升级 → 0.2 反向提问 → ...
```

**关键顺序**：`classify` 是纯文本操作，**不需要任务目录**，所以在建任何文件之前就能跑——这才是真正的「第一步」。`init` 才需要目录。

## 二、分流规则表（硬编码，不靠 AI 自觉）

判定顺序：**绝对 SKIP（S1/S2/S4/S5）→ 延续性修改 S3（须无任务动词）→ OPTIMIZE 任务动词 → 默认 SKIP**。

| # | 类别 | 判定信号 | 动作 |
|---|---|---|---|
| S1 | 寒暄致谢 | 去掉标点空白后整体是「你好 / 谢谢 / 辛苦了 / 收到 / 早上好 / ok / 再见」等 | SKIP |
| S2 | 纯事实问答 / 翻译 / 摘要 | `XX 是什么`、`是什么意思`、`译成`、`翻译`、`摘要一下`、`概括一下`、`提炼要点`，且**不含产出物信号** | SKIP |
| S3 | 延续性修改 | `继续 / 接着 / 换成 / 改成 / 再短一点 / 同上 / 按上一版 / 把第 N 行 / 撤回`，且**不含任务动词** | SKIP |
| S4 | 已点名技能或文件 | `@skill:` `/命令` `cht-best-skill` 明确路径 `~/` `/workspace/` `.md/.py/.skill` "用这个技能" | SKIP |
| S5 | 只要判断不要优化 | `不要优化 / 别优化 / 不用优化 / 禁止优化 / 只要判断 / 有.*嫁接点 / 你怎么看` | SKIP |
| T | 任务型（OPTIMIZE） | 下任务 / 归纳总结 / 生成 / 安装 / 修复 / 转换 / 推送 / 落地 / 迭代 / 嫁接 / 打包 / 创建 / 部署 / 重构 / 排查 / 撰写 / 实现 / 开发 / 制作 / 产出文件 / 发布 / 导出 / 写一份 / 做一个 | OPTIMIZE |

三条边界规则：

1. **含产出物信号优先**：「继续把报告写完并推送」同时命中 S3 与 T，判 **OPTIMIZE**（有推送/报告）。延续性修改只有在**纯局部微调**时才 SKIP。
2. **「归纳总结」是任务型，「摘要一下」是 SKIP**：区别在「纯」字与产出物。「归纳总结这份 200 页报告并产出结论文件」补得出隐性需求；「摘要一下」没有。
3. **不明确 → 默认 SKIP**。宁可少优化一次，也不给单轮问答堆流程。用户显式说「优化这段」或 `--force` 才强制 OPTIMIZE。

> 自指的例子：上一轮用户问「**这个提示词有合并嫁接点吗？**」——按 S5 应 **SKIP**，用户要的是判断，不是一份被改写过的提示词。本轮用户说「**把这段提示词也嫁接进去……完成之后迭代升级**」——命中「嫁接 / 迭代」→ OPTIMIZE。

**SKIP 的三条硬保证**（由脚本保证，不靠提示词自觉）：

- `classify` 输出 `VERDICT=SKIP` 与命中规则，动作栏明确写「原样透传，一个字不改」；
- `init --input "<SKIP 类文本>"` **直接拒绝并返回 1**，不创建任何区块、不写任何文件；
- `verify` 若发现区块里 S 段写成 SKIP，**阻断**（禁止优化的输入被优化了）。

## 三、三处冲突与调和

### ① 「自动加上角色设定」vs 连续五版「不设角色」

这是第五次撞上同一条红线：V0.0.3 黄仁勋法「从不给 AI 设角色」→ V0.0.4「不演专家」→ V0.0.5「职责契约 ≠ 人设」→ V0.0.6「审查镜头 ≠ 人设」→ V0.0.7「论证位 ≠ 人设」。

原提示词第一句「你现在是**顶级的** AI 提示词架构师」，正是会拉高讨好属性的形容词人设。

**调和**：

| | 允许 | 禁止 |
|---|---|---|
| 优化器自述 | 「本次职能是提示词架构」——界定这次干什么 | 把这句话写进交付产物 |
| 产物里的「角色设定」 | **职责契约**：要产出什么 / 验收标准 / 不做什么 | 「你是资深 XX 专家」「化身 / 扮演 / 顶级 / 大师 / 权威」 |

`verify` 真拦 B 段的人设词，不是只写在文档里。**招的是位子，不是演员**——第五次复用。

### ② 「自动补齐隐性需求」vs 心法 03 不脑补 / V0.0.6 反向提问

V0.0.6 说「AI 先问清所有信息模糊、缺失的点再干活，避免自行脑补跑偏」；这里却要「自动补齐没说出口的隐性需求」。看着正面对撞。

**调和**：补的不是「事实」，是**可修改的假设**。

- 每条隐性需求必须标 `[假设]` 并落盘到 `task_plan.md`「00」区块，明写"这是我替你补的"，不得伪装成用户说过的话（心法 03 的底线是**不编造数据、出处和意图**）；
- **不打断、不追问**：用户要的是省时间，问 20 个问题正好违反心法 06。补齐项反而成为 V0.0.6 B 段的素材——只有「不问就会跑偏」的高杠杆项才拿去批量问一次；
- **目标、范围、验收标准不改写**：优化的是提示词，不是用户的意图。

### ③ 「适配所有 AGENT 智能体」vs 「规避无效指令」

这两条在原文里是同一句话的后半段，其实互相拉扯：为"所有平台"硬编码一长串私有特性，产出的恰恰是**无法验证的无效指令**。

**调和**：通用内核（四件事不变）+ 少数**可验证**差异 + **未知平台一律回退通用档**。`profiles` 只列 5 档，且每档写明「不能写什么」。宁可少适配，不编造。

## 四、与既有七层 + 决策关的咬合

| 已有能力 | 本关怎么用 |
|---|---|
| 野心层（V0.0.4） | **高阶顶配版直接接高度/深度/广度**，不另造一套"顶配"标准；`verify` 强制 V2 含三维 |
| 沟通层（格赖斯四准则） | V2 必须带「信息适量 / 真实有据 / 紧扣主题 / 清晰简洁」；「不废话不凑字数」即数量准则 |
| 反向提问（V0.0.6 入口） | A 段 `[假设]` 清单 → B 段高杠杆模糊点素材；只把会跑偏的拿去批量问人 |
| 智囊团排雷（V0.0.6 出口） | F 段「已剔除 / 已规避」是排雷在**提示词层**的前置版；避免带着自相矛盾的指令开工 |
| 决策关（V0.0.7 按需） | 同为「条件触发、默认关闭」的范式；但决策关管**选哪条路**，本关管**这句话怎么说** |
| 三文件记忆 | 区块追加到 `task_plan.md`「00」，**不新增第四个文件**；原文留档支持跨会话恢复 |
| M1 消除档 / M2 ≤5 基元 | SKIP 即消除档；Step −1 不计入基元数 |
| 心法 02「说要什么不说怎么做」 | 优化只补"要什么/怎么算合格"，不替用户指定实现步骤 |
| 心法 10「对外文字人写」 | 优化产物是**草稿**，标 `[假设]`，最终用哪版由人定 |

**不重复造轮子**：V0.0.4 的野心升级本身就是"把浅层指令变高阶指令"，所以"高阶顶配版"不是第八套方法论，而是**把野心层三维提前注入提示词**，让 0 步拿到更好的输入。

## 五、字段规范

| 段 | 必填内容 | 校验点 |
|---|---|---|
| S 分流结论 | 输入原文（逐字）· 分类 = OPTIMIZE · 命中规则 · 原样留档声明 | 分类不得为 SKIP |
| A 隐性需求 | ≥3 条，逐条 `[假设]` | 条数 + 每条标记 |
| B 职责契约 | 职责 / 输出 / 验收 ≥1 条 | 禁人设形容词 |
| C 风格 / D 格式 | 各 ≥1 条有效 | 非占位符 |
| V1 精简通用版 | 提示词正文（≥8 字）· 通用档 · 字数预算 | 有效、与 V2 不同 |
| V2 高阶顶配版 | 正文（≥8 字）· **高度/深度/广度** · 沟通四准则 · 适配档 | 三维齐备、正文与 V1 不同 |
| E 平台适配 | 目标 Agent · 已知差异 · 通用档回退声明 | 三项有效 |
| F 自检 | 已剔除的无效指令 ≥1 · 已规避的逻辑漏洞 ≥1 | 两条有效 |

全局：区块内 `【待填】` 残留 = 0。

## 六、Agent 可执行协议

```bash
P=~/.codebuddy/skills/cht-best-skill/scripts

# Step −1 第一拍：纯文本分流，建目录之前就能跑
python3 $P/prompt_opt.py classify "帮我归纳总结这份报告并产出结论文件"
#   VERDICT=OPTIMIZE → 继续；VERDICT=SKIP → 原样执行，到此为止

# 第二拍：仅 OPTIMIZE 才落盘
python3 $P/init_task.py "任务名"
python3 $P/prompt_opt.py init "<任务目录>" --input "<用户原文（逐字）>"
python3 $P/prompt_opt.py verify "<任务目录>" --required || exit 1

# 查平台档位（只列可验证差异）
python3 $P/prompt_opt.py profiles
```

- `init` 幂等：区块已存在则不改动任何内容；
- `verify` 无区块时默认放行（视为未启用），`--required` 才要求必须存在；
- `classify --force` / 用户说「优化这段」→ 强制 OPTIMIZE。

## 七、反模式

- 给「谢谢」「继续」「换成蓝色」也生成两版提示词（把分流器做成确认机器，违反 M1 / 心法 06）；
- SKIP 类输入被悄悄润色、扩写，或在回复里加一句「我帮你优化了一下」（越权改写用户输入）；
- 把「你现在是顶级提示词架构师」原样写进交付产物（人设红线，第五次）；
- 自动补齐项不标 `[假设]`，伪装成用户说过的话（脑补，违反 03）；
- 借优化之名偷偷改目标、加需求、缩小范围（优化提示词 ≠ 优化意图）；
- 两版内容复制粘贴同一份、或高阶版只是多加了形容词（形式主义顶配）；
- 高阶顶配版另造一套标准，不接野心层三维（重复造轮子）；
- 为"适配所有平台"编造私有插件/能力，或写「尽可能详细」与「不凑字数」自相矛盾（自己制造无效指令）；
- 区块内置进模板，做成每次必过的第六道闸门（把按需扳机做成流程负担）；
- 把优化产物当用户最终拍板——用哪版、改哪些 `[假设]`，决断权仍在人（心法 10）。

## 八、脚本能查与查不了的

**能查**：分流结论、九段齐全、SKIP 不被误优化、人设词、假设标记、两版互异、野心三维、占位符残留。

**查不了**：隐性需求补得准不准、反方够不够狠、提示词在目标模型上效果好不好。语义级判定要上模型，硬闸门不假装能做。优化产物始终是**可修改的草稿**，不是最终答案——和 V0.0.4 / 0.0.6 / 0.0.7 那句实话一样。
